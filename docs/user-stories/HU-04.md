## Historia

**Como** huésped, **quiero** registrarme e iniciar sesión de forma segura, **para** que mis datos guardados y mis reservas solo los pueda ver y usar yo.

## Descripción y valor

Hoy toda la API es pública y no existe el concepto de usuario autenticado. Sin identidad no se pueden guardar tarjetas (HU-01), listar "mis" reservas (HU-05) ni restringir la analítica al administrador (HU-03). Esta HU introduce la cuenta del huésped, el rol `ADMIN` y la protección de rutas en API y SPA.

## Reglas de negocio

- RN-04.1: `username` (3–30, `[a-zA-Z0-9._-]`) y `email` son únicos sin distinguir mayúsculas; se guardan en minúsculas.
- RN-04.2: Contraseña de 8–72 caracteres con al menos una letra y un dígito; se guarda con BCrypt y nunca se devuelve.
- RN-04.3: El registro siempre crea rol `USER`; cualquier `role` en el body se ignora. Los `ADMIN` solo provienen del seed.
- RN-04.4: El login acepta usuario **o** email. Si falla, el mensaje es el mismo exista o no la cuenta.
- RN-04.5: El token dura 24 h. Al caducar, la SPA cierra la sesión y lleva a `/login` conservando la ruta de retorno.
- RN-04.6: Un usuario solo accede a sus propios recursos; los ajenos responden 404.
- RN-04.7: Las rutas de escritura de hoteles y `/api/admin/**` exigen `ADMIN` ([ARCHITECTURE §5.1](../architecture/ARCHITECTURE.md#51-matriz-de-acceso)).

## Criterios de aceptación

```gherkin
Escenario: CA-04.1 Registro exitoso
  Dado que no existe el usuario "ana.perez" ni el email "ana@example.com"
  Cuando envío POST /api/auth/register con datos válidos
  Entonces la respuesta es 201 con un token y user.role = "USER"
  Y la contraseña almacenada es un hash BCrypt distinto de la original

Escenario: CA-04.2 Email duplicado sin distinguir mayúsculas
  Dado un usuario con email "ana@example.com"
  Cuando me registro con email "ANA@Example.com"
  Entonces la respuesta es 409 con code "EMAIL_ALREADY_EXISTS"

Escenario: CA-04.3 Contraseña débil
  Cuando me registro con la contraseña "abcdefgh"
  Entonces la respuesta es 400 con code "VALIDATION_ERROR" y errors.password informado

Escenario: CA-04.4 Intento de auto-asignarse ADMIN
  Cuando me registro enviando además "role": "ADMIN"
  Entonces la respuesta es 201 y user.role = "USER"

Escenario: CA-04.5 Login con usuario o con email
  Dado el usuario "ana.perez" con email "ana@example.com" y contraseña "Secreta123"
  Cuando inicio sesión con "ana.perez" o con "ANA@example.com"
  Entonces en ambos casos la respuesta es 200 con token

Escenario: CA-04.6 Credenciales incorrectas sin enumerar usuarios
  Cuando inicio sesión con una contraseña incorrecta o con un usuario inexistente
  Entonces en ambos casos la respuesta es 401 con code "INVALID_CREDENTIALS" y el mismo mensaje

Escenario: CA-04.7 Perfil propio
  Dado un token válido de "ana.perez"
  Cuando hago GET /api/auth/me
  Entonces recibo 200 con su perfil y sin el campo password

Escenario: CA-04.8 Petición protegida sin token o con token caducado
  Cuando hago GET /api/auth/me sin cabecera Authorization, o con un token caducado
  Entonces la respuesta es 401 con cuerpo {"message": "...", "code": "UNAUTHORIZED"}

Escenario: CA-04.9 Rol insuficiente
  Dado un token de un USER
  Cuando hago GET /api/admin/analytics/demand-forecast o POST /api/hotel/registration-hotel
  Entonces la respuesta es 403 con code "FORBIDDEN"

Escenario: CA-04.10 Rutas públicas siguen públicas
  Cuando hago GET /api/hotel/get-all o GET /api/rooms sin token, o con un token inválido
  Entonces la respuesta no es 401

Escenario: CA-04.11 Login en la SPA con retorno
  Dado que estoy en /my-reservations sin sesión
  Entonces soy redirigido a /login?redirect=%2Fmy-reservations
  Cuando inicio sesión correctamente
  Entonces vuelvo a /my-reservations y la cabecera muestra mi nombre y "Cerrar sesión"

Escenario: CA-04.12 Persistencia y cierre de sesión
  Dado que inicié sesión
  Cuando recargo la página, sigo autenticado
  Y cuando pulso "Cerrar sesión", la sesión desaparece de localStorage y vuelvo a "/"

Escenario: CA-04.13 Sesión caducada durante el uso
  Dado que tengo sesión y el backend responde 401 UNAUTHORIZED a una petición protegida
  Entonces la SPA borra la sesión y me lleva a /login?redirect=<ruta actual>

Escenario: CA-04.14 Panel admin solo para ADMIN
  Dado que inicié sesión como USER
  Cuando navego a /admin
  Entonces soy redirigido a "/" y no se muestra el panel
```

## Endpoints y pantallas

- Endpoints: [§2.1 register](../architecture/API-CONTRACT.md#21-post-apiauthregister--público), [§2.2 login](../architecture/API-CONTRACT.md#22-post-apiauthlogin--público), [§2.3 me](../architecture/API-CONTRACT.md#23-get-apiauthme--autenticado-user-o-admin); seguridad de §7 (hoteles).
- Pantallas: `/login` (nueva), `/register` (nueva), `Header` (enlaces "Iniciar sesión"/"Registrarse" o menú con "Mis reservas", "Mis tarjetas", "Panel admin" si es ADMIN, "Cerrar sesión"), `/admin` protegido.

## Definición de Hecho

Cumple la [DoD común](README.md#definición-de-hecho-común) y además: ningún endpoint fuera de la lista pública de ARCHITECTURE §5.1 responde 200 sin token (lo verifica `SecurityRulesTest`), y `password` no aparece en ninguna respuesta.
