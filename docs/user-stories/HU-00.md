## Historia

**Como** equipo de desarrollo, **quiero** un proyecto que compile, arranque y se pruebe automáticamente sin instalar PostgreSQL, **para** que cada historia se entregue con tests en CI y sin "en mi máquina funciona".

## Descripción y valor

El repo heredado no arrancaba sin un PostgreSQL local con `root/root`, su único test necesitaba la base de datos, el frontend no compilaba (`tsc -b`) y no había CI. Esta HU deja la plataforma lista: perfiles, H2, CI, cliente HTTP tipado y un formato de error único que el frontend pueda interpretar por `code`. Diagnóstico completo en [ARCHITECTURE §2](../architecture/ARCHITECTURE.md#2-diagnóstico-del-estado-actual).

## Reglas de negocio / técnicas

- RN-00.1: `./mvnw spring-boot:run` sin variables de entorno arranca con el perfil `dev` (H2 + seed) en el puerto 3000.
- RN-00.2: `./mvnw test` no necesita servicios externos (perfil `test`).
- RN-00.3: No hay secretos reales en el repo. Las credenciales de BD de `postgres` vienen de `DB_URL`, `DB_USERNAME` y `DB_PASSWORD`.
- RN-00.4: Toda respuesta de error usa `ApiResponse{message, code?, errors?}` ([API-CONTRACT §0.1](../architecture/API-CONTRACT.md#01-sobre-de-error-apiresponse-extendido)). `code` y `errors` se omiten si no aplican.
- RN-00.5: Nadie llama a `LocalDate.now()` ni a `LocalDateTime.now()` sin pasar el `Clock`.
- RN-00.6: Un PR a `develop` o `main` no se fusiona con la CI en rojo.

## Criterios de aceptación

```gherkin
Escenario: CA-00.1 Tests de backend sin PostgreSQL
  Dado un clon limpio del repositorio sin PostgreSQL instalado
  Cuando ejecuto "./mvnw test" en hotel-reservation-system-backend
  Entonces todos los tests pasan usando H2 con el perfil "test"

Escenario: CA-00.2 Arranque de desarrollo con datos semilla
  Dado que no defino ninguna variable de entorno
  Cuando ejecuto "./mvnw spring-boot:run"
  Entonces la aplicación arranca en el puerto 3000 con el perfil "dev"
  Y GET /api/hotel/get-all responde 200 con los 2 hoteles semilla

Escenario: CA-00.3 Parámetro con tipo inválido
  Cuando hago GET /api/hotel/get-hotel/abc
  Entonces la respuesta es 400
  Y el cuerpo es {"message": "...", "code": "INVALID_PARAMETER"}

Escenario: CA-00.4 JSON mal formado
  Cuando envío POST /api/hotel/registration-hotel con el cuerpo "{nombre:"
  Entonces la respuesta es 400 con code "MALFORMED_REQUEST"
  Y el cuerpo no contiene trazas de pila

Escenario: CA-00.5 Error inesperado
  Dado un servicio que lanza una RuntimeException no controlada
  Cuando se invoca su endpoint
  Entonces la respuesta es 500 con code "INTERNAL_ERROR" y un mensaje genérico en español

Escenario: CA-00.6 Frontend compila y se prueba
  Cuando ejecuto "npm ci && npm test && npm run build" en hotel-reservation-system-frontend
  Entonces los tres comandos terminan con código 0

Escenario: CA-00.7 Cliente HTTP tipado
  Dado que el backend responde 409 con {"message":"x","code":"ROOM_NOT_AVAILABLE"}
  Cuando el frontend llama a la API mediante api/client.ts
  Entonces se lanza un ApiError con status 409 y code "ROOM_NOT_AVAILABLE"
  Y si hay token en sesión la petición lleva la cabecera "Authorization: Bearer <token>"

Escenario: CA-00.8 La CI bloquea código roto
  Dado un PR hacia develop con un test que falla
  Cuando se ejecuta el workflow "CI"
  Entonces el job correspondiente queda en rojo y el PR no se puede fusionar
```

Nota: a partir de HU-04 las rutas de escritura de hoteles exigen ADMIN. El test de CA-00.4 debe enviar entonces un token de ADMIN (lo ajusta HU-04).
