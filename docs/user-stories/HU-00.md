## Historia

**Como** equipo de desarrollo, **quiero** que `developer` compile, arranque sin PostgreSQL y tenga tests automáticos de su comportamiento actual, **para** poder modificarlo en cada historia sin romper lo que ya funciona.

## Descripción y valor

`developer` no compila en frontend (`tsc -b`), no tiene tests, exige PostgreSQL con `root/root` y no tiene manejo de errores común (ARCHITECTURE §2, B8, B12–B15, B17, F1, F2, F10). Esta HU **porta** la base técnica ya hecha sobre `main` (archivada) y añade **tests de caracterización**: fijan el estado HTTP y la forma actuales de cada endpoint existente, de modo que cualquier cambio posterior se vea en el diff de los tests.

## Reglas técnicas

- RN-00.1: `./mvnw spring-boot:run` sin variables arranca con el perfil `dev` (H2 + seed) en el puerto 3000.
- RN-00.2: `./mvnw test` no necesita servicios externos (perfil `test`).
- RN-00.3: Sin secretos reales en el repo; `postgres` lee `DB_URL`, `DB_USERNAME` y `DB_PASSWORD`.
- RN-00.4: Un único sobre de error `ApiResponse{message, code?, errors?}` producido por `GlobalExceptionHandler` ([API-CONTRACT §0.1](../architecture/API-CONTRACT.md#01-sobre-de-error-único-apiresponse-extendido)).
- RN-00.5: Nadie llama a `LocalDate.now()`/`LocalDateTime.now()` sin el `Clock`.
- RN-00.6: Los tests de caracterización describen lo que **hace** el sistema hoy, no lo que debería. Cambiarlos exige justificarlo en el PR de la HU que cambia el comportamiento.
- RN-00.7: Un PR a `develop` o `main` no se fusiona con la CI en rojo.

## Criterios de aceptación

```gherkin
Escenario: CA-00.1 Mapeo de amenities portable (primera tarea)
  Dado el perfil "test" con H2 en modo PostgreSQL
  Cuando persisto una Room con amenities ["Free WiFi", "Jacuzzi"] y la vuelvo a leer
  Entonces recupero la misma lista en el mismo orden
  # Si falla, se cambia el mapeo a @ElementCollection antes de seguir (ADR-002)

Escenario: CA-00.2 Tests de backend sin PostgreSQL
  Dado un clon limpio sin PostgreSQL
  Cuando ejecuto "./mvnw test"
  Entonces todos los tests pasan con H2

Escenario: CA-00.3 Arranque de desarrollo con datos semilla
  Dado que no defino variables de entorno
  Cuando ejecuto "./mvnw spring-boot:run"
  Entonces la aplicación arranca en el puerto 3000 con el perfil "dev"
  Y GET /api/hotel/get-all responde 200 con 2 hoteles
  Y puedo iniciar sesión con "admin@hotel.com" / "Admin12345" y con "demo@hotel.com" / "Demo12345"

Escenario: CA-00.4 Caracterización de los endpoints existentes
  Dado el perfil "test"
  Cuando se ejecutan los tests de caracterización de /auth, /api/hotel, /api/room, /api/reservation, /api/payment, /api/review y /api/user
  Entonces cada test fija el estado HTTP y los campos JSON observados hoy, en casos de éxito, no encontrado y sin token

Escenario: CA-00.5 Sobre de error en parámetros inválidos
  Cuando hago GET /api/hotel/get-hotel/abc
  Entonces la respuesta es 400 con code "INVALID_PARAMETER" y sin traza de pila

Escenario: CA-00.6 Frontend compila y se prueba
  Cuando ejecuto "npm ci && npm test && npm run build" en hotel-reservation-system-frontend
  Entonces los tres comandos terminan con código 0

Escenario: CA-00.7 Las rutas que usa el frontend no cambian
  Cuando se ejecutan los tests de services/*.ts con axios simulado
  Entonces fetchRooms llama a "/api/room/get-all", getRoomById a "/api/room/get-room/{id}", getCurrentUser a "/api/user/current", y así con cada función existente

Escenario: CA-00.8 CORS para todos los controladores
  Cuando el navegador hace una petición preflight OPTIONS desde http://localhost:5173 a /api/reservation/get-all
  Entonces la respuesta incluye Access-Control-Allow-Origin: http://localhost:5173

Escenario: CA-00.9 La CI bloquea código roto
  Dado un PR hacia develop con un test que falla
  Entonces el job correspondiente queda en rojo y el PR no se puede fusionar
```

## Endpoints y pantallas afectados

- Endpoints: ninguno nuevo. Todos los existentes quedan caracterizados; los errores de framework pasan al sobre común.
- Pantallas: ninguna visible. Solo se corrigen errores de compilación.
