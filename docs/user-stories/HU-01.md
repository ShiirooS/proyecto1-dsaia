## Historia

**Como** usuario recurrente, **quiero** reservar directamente usando mis datos guardados, **para** no tener que rellenar el formulario de pago en cada compra.

## Descripción y valor

Hoy no se puede reservar: el botón "Reserve" no hace nada y no existe el pago. Esta HU crea el flujo de checkout completo: tarjeta nueva con opción "guardar para próximas compras" y, para el usuario recurrente, reserva en un clic con su tarjeta predeterminada. El pago es simulado y solo se guarda una referencia tokenizada (ADR-003). El valor de negocio es una conversión más alta para clientes que repiten, con menos fricción.

## Reglas de negocio

- RN-01.1: Se guarda solo `token`, `brand`, `last4`, `expMonth`, `expYear` y `holderName`. Nunca el número completo ni el CVV, tampoco en logs.
- RN-01.2: Marcas aceptadas: VISA, MASTERCARD y AMEX, con Luhn, longitud y CVV por marca, y tarjeta no vencida ([API-CONTRACT §8](../architecture/API-CONTRACT.md#8-tarjetas-de-prueba-pasarela-simulada)).
- RN-01.3: La primera tarjeta guardada queda como predeterminada. Solo hay una predeterminada por usuario. Si se borra la predeterminada, pasa a serlo la más reciente.
- RN-01.4: Con tarjeta guardada no se pide CVV.
- RN-01.5: `totalAmount = noches × pricePerNight`, calculado **en el servidor** (el cliente no envía precios).
- RN-01.6: Reglas de fechas y huéspedes de [API-CONTRACT §5.1](../architecture/API-CONTRACT.md#51-post-apireservations--autenticado) (pasado, check-out ≤ check-in, > 30 noches, > 365 días, capacidad).
- RN-01.7: El solapamiento se comprueba con la habitación bloqueada; si hay conflicto → 409 y no se cobra.
- RN-01.8: Pago rechazado (tarjeta terminada en 0002) → 402 y no se persiste nada: ni reserva, ni pago, ni tarjeta.
- RN-01.9: Si `saveCard=true` y la tarjeta ya estaba guardada, la reserva no falla: se reutiliza la existente.
- RN-01.10: Un usuario no puede usar ni ver métodos de pago de otro (404).

## Criterios de aceptación

Contexto común: usuario `demo` con sesión iniciada, habitación 3 a 150.00/noche libre del 2026-12-20 al 2026-12-23, `today = 2026-10-28`.

```gherkin
Escenario: CA-01.1 Reserva en un clic con la tarjeta predeterminada
  Dado que "demo" tiene guardada una VISA terminada en 4242 como predeterminada
  Cuando elijo del 20 al 23 de diciembre y pulso "Reservar"
  Entonces el checkout muestra "3 noches · 450.00" y la VISA •••• 4242 preseleccionada sin pedir CVV
  Cuando pulso "Pagar 450.00"
  Entonces POST /api/reservations con paymentMethodId responde 201
  Y veo la confirmación con el número de reserva y el pago "VISA •••• 4242"

Escenario: CA-01.2 Primera compra con tarjeta nueva y guardarla
  Dado un usuario sin tarjetas guardadas
  Cuando pago con 5555 5555 5555 4444 y marco "Guardar tarjeta para próximas compras"
  Entonces la reserva se crea con 201 y savedPaymentMethodId tiene valor
  Y en mi próxima reserva esa MASTERCARD •••• 4444 aparece preseleccionada como predeterminada

Escenario: CA-01.3 Tarjeta nueva sin guardar
  Cuando pago con una tarjeta nueva sin marcar "Guardar"
  Entonces la reserva se crea y GET /api/payment-methods no incluye esa tarjeta

Escenario: CA-01.4 Pago rechazado
  Cuando pago con 4000 0000 0000 0002 marcando "Guardar"
  Entonces la respuesta es 402 con code "PAYMENT_DECLINED"
  Y se muestra "El pago fue rechazado. Prueba con otra tarjeta."
  Y no se creó ninguna reserva, pago ni método de pago

Escenario: CA-01.5 Tarjeta inválida o vencida
  Cuando introduzco 4242 4242 4242 4241
  Entonces el formulario marca "Número de tarjeta inválido" antes de enviar
  Y si la petición llega al servidor, este responde 422 con code "CARD_INVALID"
  Y con una fecha de expiración pasada el servidor responde 422 con code "CARD_EXPIRED"

Escenario: CA-01.6 Las fechas se ocuparon mientras pagaba
  Dado que otro usuario reservó el 21 de diciembre después de que yo eligiera mis fechas
  Cuando pulso "Pagar"
  Entonces la respuesta es 409 con code "ROOM_NOT_AVAILABLE" y no se cobra
  Y vuelvo al calendario, que muestra el 21 como ocupado, con el mensaje "Esas fechas acaban de reservarse"

Escenario: CA-01.7 Fuente de pago ambigua
  Cuando envío POST /api/reservations con paymentMethodId y card a la vez, o sin ninguno
  Entonces la respuesta es 400 con code "INVALID_PAYMENT_SOURCE"

Escenario: CA-01.8 Reglas de estancia
  Cuando reservo con checkIn en el pasado, checkOut <= checkIn, 31 noches o 3 huéspedes en una habitación de capacidad 2
  Entonces recibo 422 con CHECKIN_IN_PAST, INVALID_STAY_DATES, MAX_NIGHTS_EXCEEDED o GUESTS_EXCEED_CAPACITY respectivamente

Escenario: CA-01.9 No se almacenan datos sensibles
  Dado que reservé con 4242 4242 4242 4242 y CVV 123 marcando "Guardar"
  Entonces ninguna fila de payment_method ni de payments contiene "4242424242424242" ni el CVV
  Y ninguna respuesta de la API contiene el token "tok_..."

Escenario: CA-01.10 Gestión de tarjetas
  Dado que tengo una VISA predeterminada y una MASTERCARD
  Cuando en /account/payment-methods marco la MASTERCARD como predeterminada
  Entonces es la única con isDefault = true
  Cuando la elimino
  Entonces la VISA vuelve a ser la predeterminada

Escenario: CA-01.11 Tarjeta duplicada
  Cuando guardo desde /account/payment-methods una tarjeta con la misma marca, últimos 4 y expiración que una existente
  Entonces la respuesta es 409 con code "DUPLICATE_PAYMENT_METHOD"
  Pero si reservo con esa tarjeta y "Guardar" marcado, la reserva se crea y savedPaymentMethodId es el id existente

Escenario: CA-01.12 Tarjeta de otro usuario
  Dado que la tarjeta 5 pertenece a otro usuario
  Cuando reservo con paymentMethodId 5, o hago DELETE /api/payment-methods/5
  Entonces la respuesta es 404 con code "PAYMENT_METHOD_NOT_FOUND"

Escenario: CA-01.13 Checkout sin sesión
  Dado que no tengo sesión
  Cuando pulso "Reservar" en /rooms/3 con fechas elegidas
  Entonces voy a /login y, tras iniciar sesión, vuelvo al checkout con las mismas fechas y huéspedes

Escenario: CA-01.14 Doble clic
  Cuando pulso "Pagar" dos veces seguidas
  Entonces el botón queda deshabilitado tras el primer clic y se envía un único POST
```

- [ ] `domain/CardValidator` (normalizar, marca, Luhn, longitud, CVV, expiración con `YearMonth.now(clock)`).
- [ ] `service/PaymentGateway` + `service/imp/SimulatedPaymentGateway` (`tokenize`, `charge`, `refund`; `SecureRandom`).
- [ ] `PaymentMethodService`/`Imp` + `controller/PaymentMethodController` (4 endpoints; cambio de predeterminada transaccional).
