## Historia

**Como** usuario recurrente, **quiero** reservar directamente usando mis datos guardados, **para** no tener que rellenar el formulario de pago en cada compra.

## Descripción y valor

En `developer`, "Book now" abre `ConfirmBookingModal`, que pide nombre, teléfono y fechas y solo hace `console.log`. `POST /api/reservation/registration-reservation` existe, pero toma el `userId` del body, no cobra y (tras HU-04) es solo para ADMIN. Esta HU convierte el modal en el paso de pago: tarjeta nueva con opción "guardar para próximas compras" y, para el usuario recurrente, reserva en un clic con su tarjeta predeterminada. El pago es simulado y solo se guarda una referencia tokenizada (ADR-003). El valor de negocio es más conversión de clientes que repiten, con menos fricción.

## Reglas de negocio

- RN-01.1: Se guarda solo `token`, `brand`, `last4`, `expMonth`, `expYear` y `holderName`. Nunca el número completo ni el CVV, tampoco en logs.
- RN-01.2: Marcas VISA, MASTERCARD y AMEX, con Luhn, longitud y CVV por marca, y tarjeta no vencida ([API-CONTRACT §11](../architecture/API-CONTRACT.md#11-tarjetas-de-prueba-pasarela-simulada)).
- RN-01.3: La primera tarjeta guardada queda como predeterminada; solo hay una por usuario. Si se borra la predeterminada, pasa a serlo la más reciente.
- RN-01.4: Con tarjeta guardada no se pide CVV.
- RN-01.5: `totalAmount = noches × pricePerNight` (entero), calculado **en el servidor**.
- RN-01.6: Reglas de fechas y huéspedes de [API-CONTRACT §6.1](../architecture/API-CONTRACT.md#61-post-apireservationbook--autenticado--nuevo).
- RN-01.7: El solapamiento se comprueba con la habitación bloqueada; si hay conflicto → 409 y no se cobra.
- RN-01.8: Pago rechazado (tarjeta terminada en 0002) → 402 y no se persiste nada (ni reserva, ni pago, ni tarjeta).
- RN-01.9: Si `saveCard=true` y la tarjeta ya estaba guardada, la reserva no falla: se reutiliza la existente.
- RN-01.10: Un usuario no puede usar ni ver métodos de pago de otro (404). El usuario de la reserva sale del token.

## Criterios de aceptación

Contexto común: `demo@hotel.com` con sesión, habitación 3 a 150/noche libre del 2026-12-20 al 2026-12-23, `today = 2026-10-28`.

```gherkin
Escenario: CA-01.1 Reserva en un clic con la tarjeta predeterminada
  Dado que "demo" tiene guardada una VISA terminada en 4242 como predeterminada
  Cuando en /roomDetail/3 elijo del 20 al 23 de diciembre y pulso "Book now"
  Entonces ConfirmBookingModal muestra "3 noches · $450" y la VISA •••• 4242 preseleccionada sin pedir CVV
  Cuando pulso "Pagar $450"

  Y el modal muestra la confirmación con el número de reserva, "VISA •••• 4242" y un enlace a /bookings

  Dado un usuario sin tarjetas guardadas
  Cuando pago con 5555 5555 5555 4444 y marco "Guardar tarjeta para próximas compras"
  Entonces la reserva se crea con 201 y savedPaymentMethodId tiene valor
  Y en mi próxima reserva esa MASTERCARD •••• 4444 aparece preseleccionada

Escenario: CA-01.3 Tarjeta nueva sin guardar

  Entonces la reserva se crea y GET /api/payment-method/get-all no incluye esa tarjeta

Escenario: CA-01.4 Pago rechazado
  Cuando pago con 4000 0000 0000 0002 marcando "Guardar"
  Entonces la respuesta es 402 con code "PAYMENT_DECLINED"

  Cuando introduzco 4242 4242 4242 4241
  Entonces el formulario marca "Número de tarjeta inválido" antes de enviar
  Y si la petición llega al servidor, este responde 422 con code "CARD_INVALID"
  Y con una expiración pasada el servidor responde 422 con code "CARD_EXPIRED"

Escenario: CA-01.6 Las fechas se ocuparon mientras pagaba
  Dado que otro usuario reservó el 21 de diciembre después de que yo eligiera mis fechas
  Cuando pulso "Pagar"
  Entonces la respuesta es 409 con code "ROOM_NOT_AVAILABLE" y no se cobra

Escenario: CA-01.7 Fuente de pago ambigua
  Cuando envío POST /api/reservation/book con paymentMethodId y card a la vez, o sin ninguno
  Entonces la respuesta es 400 con code "INVALID_PAYMENT_SOURCE"

Escenario: CA-01.9 No se almacenan datos sensibles
  Dado que reservé con 4242 4242 4242 4242 y CVV 123 marcando "Guardar"
  Entonces ninguna fila de payment_method ni de payments contiene "4242424242424242" ni el CVV
  Y ninguna respuesta de la API contiene el token "tok_..."

Escenario: CA-01.10 Gestión de tarjetas
  Dado que tengo una VISA predeterminada y una MASTERCARD
  Cuando en /payment-methods marco la MASTERCARD como predeterminada
  Entonces es la única con isDefault = true
  Cuando la elimino
  Entonces la VISA vuelve a ser la predeterminada

Escenario: CA-01.11 Tarjeta duplicada
  Cuando guardo en /payment-methods una tarjeta con la misma marca, últimos 4 y expiración que otra existente
  Entonces la respuesta es 409 con code "DUPLICATE_PAYMENT_METHOD"
  Pero si reservo con esa tarjeta y "Guardar" marcado, la reserva se crea y savedPaymentMethodId es el id existente

Escenario: CA-01.12 Tarjeta de otro usuario
  Dado que la tarjeta 5 pertenece a otro usuario
  Cuando reservo con paymentMethodId 5, o hago DELETE /api/payment-method/delete-payment-method/5
  Entonces la respuesta es 404 con code "PAYMENT_METHOD_NOT_FOUND"

Escenario: CA-01.13 Reservar sin sesión
  Dado que no tengo sesión y elegí fechas en /roomDetail/3
  Cuando pulso "Book now"
  Entonces se abre el modal de login del Header y, tras iniciar sesión, vuelvo a /roomDetail/3 y se abre ConfirmBookingModal con las mismas fechas

Escenario: CA-01.14 Doble clic
  Cuando pulso "Pagar" dos veces seguidas
  Entonces el botón queda deshabilitado tras el primer clic y se envía un único POST

Escenario: CA-01.15 Los pagos aparecen en el panel
  Dado que "demo" reservó con éxito
  Cuando un ADMIN consulta GET /api/payment/get-all
  Entonces el pago aparece con status "COMPLETED", amount 450, cardBrand y cardLast4
```

## Endpoints y pantallas

- Endpoints: [§5 métodos de pago](../architecture/API-CONTRACT.md#5-métodos-de-pago-guardados-hu-01) (todo nuevo), [§6.1 `POST /api/reservation/book`](../architecture/API-CONTRACT.md#61-post-apireservationbook--autenticado--nuevo), §6.3 `GET /api/reservation/my-reservations/{id}`, campos aditivos en `/api/payment/*` ([§7](../architecture/API-CONTRACT.md#7-pagos-administración)).
- Pantallas: `components/Modals/ConfirmBookingModal.tsx` (rediseñado como paso de pago), `/payment-methods` (nueva `PaymentMethodsPage`, enlazada desde `ProfileCircle`).

## Tareas técnicas

**Backend**
- [ ] Entidad `PaymentMethod` + `PaymentMethodRepository` (`findByUserIdOrderByIsDefaultDescCreatedAtDesc`, `findByIdAndUserId`, `existsByUserIdAndBrandAndLast4AndExpMonthAndExpYear`); `enums/CardBrand`.
- [ ] `Payment`: `cardBrand`, `cardLast4`, `transactionId`, `refundedAmount` (`Integer`, 0); `PaymentStatus` + `REFUNDED`; `PaymentDTO` con los campos nuevos.
- [ ] `Reservation`: `guests` y `totalAmount` (`Integer`).
- [ ] `domain/CardValidator` (normalizar, marca, Luhn, longitud, CVV, expiración con `YearMonth.now(clock)`).
- [ ] `service/PaymentGateway` + `service/imp/SimulatedPaymentGateway` (`tokenize`, `charge`, `refund`; `SecureRandom`).
- [ ] `PaymentMethodService`/`Imp` + `controller/PaymentMethodController` (4 endpoints de §5).
- [ ] `ReservationService.book` (`@Transactional`, orden de pasos de §6.1, `RoomRepository.findByIdForUpdate`, usuario del token) y `getMyReservation(id)`; DTO de respuesta `MyReservationDTO` con `cancellation` (crea `domain/CancellationPolicy`, que amplía HU-05).
- [ ] `ReservationController`: `POST /api/reservation/book` (201 + `Location`), `GET /api/reservation/my-reservations/{id}`.
- [ ] DTOs de tarjeta con `@ToString.Exclude` en `cardNumber` y `cvv`; `@JsonProperty("isDefault")`.
- [ ] `DevDataSeeder`: VISA ••••4242 predeterminada para `demo`.

**Frontend**
- [ ] `services/paymentMethodService.ts` y `services/reservationService.ts` (`bookReservation`, `getMyReservation`) sobre la instancia axios; tipos de API-CONTRACT §1.
- [ ] `components/Payment/cardUtils.ts` (Luhn, marca, formato; solo para UX), `components/Payment/CardForm.tsx` (número, MM/AA, CVV, titular, "Guardar"; `autocomplete="cc-*"`; el número nunca va a estado global ni a `localStorage`), `components/Payment/PaymentMethodSelector.tsx` (tarjetas guardadas + "Usar otra tarjeta"; preselecciona la predeterminada; desactiva las vencidas).
- [ ] `ConfirmBookingModal.tsx`: recibe `{room, checkIn, checkOut, guests}` de `RoomDetailsPage`; quita los campos nombre, teléfono y fechas; muestra el resumen, el selector y `CardForm`; maneja 402/409/422 por `code` con `toApiError`; deshabilita "Pagar" mientras envía; estado de confirmación.
- [ ] `pages/PaymentMethodsPage.tsx` (listar, añadir, eliminar con confirmación, marcar predeterminada) + ruta `/payment-methods` (`ProtectedRoute role="USER"`) + enlace en `ProfileCircle`.
- [ ] `RoomDetailsPage`: sin sesión, "Book now" abre el login (`?login=1&redirect=/roomDetail/3`) y conserva la selección (estado en la URL: `?checkIn&checkOut&guests`).
